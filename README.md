# NixOS Home Server

A declarative NixOS home server deploying Nextcloud, AdGuard Home, Caddy, Fail2ban and automatic security updates. Configuration is generated by a graphical Python tool. No Nix knowledge is required to deploy.

```
NixOSHome/
├── flake.nix                 # Flake definition and inputs
├── config/
│   ├── configuration.nix     # Core system, SSH, Fail2ban
│   ├── hardware.nix          # Boot loader and kernel
│   └── disko.nix             # Disk partitioning layout
├── modules/
│   ├── users.nix
│   ├── networking.nix
│   ├── secrets.nix
│   ├── adguard.nix
│   ├── caddy.nix
│   ├── nextcloud.nix
│   └── auto-upgrade.nix
├── options/
│   ├── options.nix           # Generated by nixgen.py
│   ├── secrets.yaml          # Encrypted by SOPS after generation
│   └── .sops.yaml            # SOPS key policy
└── generator/
    ├── nixgen.py             # The configuration generator
    └── shell.nix             # Nix shell providing Python and tkinter
```

The `options/` directory contains placeholder files used for the reference deployment. You will regenerate all three files for your own hardware.

---

## Prerequisites

### Workstation

- Linux or macOS with Nix installed and flakes enabled
- Git
- A GitHub account (the flake is deployed by reference to a GitHub URL)

If Nix is not installed, follow the official installer at https://nixos.org/download.

To enable flakes, add the following to `/etc/nix/nix.conf` or `~/.config/nix/nix.conf`:

```
experimental-features = nix-command flakes
```

### Target Machine

- A machine booted into a Linux environment reachable over SSH as root (a NixOS minimal ISO or Ubuntu live image works)
- Two storage devices: one for the operating system, one for data
- The OS disk will be fully wiped and repartitioned by Disko. Back up anything on it before proceeding.
- The data disk must already be formatted as ext4. Disko does not partition it. To format it:

```bash
# Run on the target machine. Replace /dev/sda with your device.
mkfs.ext4 /dev/sda
```

## Step 1: Fork and Clone the Repository

Fork the repository to your own GitHub account. Then clone your fork:

```bash
git clone https://github.com/YOUR_USERNAME/NixOSHome.git
cd NixOSHome
```

Replace `YOUR_USERNAME` with your GitHub username. The deployment step pulls the configuration directly from GitHub, so the fork must be on your account.

---

## Step 2: Gather Values for the Generator

Collect the following before running the generator.

**Your SSH public key** (from your workstation):

```bash
cat ~/.ssh/id_ed25519.pub
```

If you do not have an SSH key pair, generate one first:

```bash
ssh-keygen -t ed25519
```

**Network interface name** (from the target machine):

```bash
ip link show
```

Look for the name of the wired interface, typically something like `enp3s0` or `eth0`. Do not use `lo`.

**Disk device paths** (from the target machine):

```bash
lsblk -d -o NAME,SIZE,MODEL
```

Note the full device path for the OS disk (e.g. `/dev/nvme0n1`) and the data partition (e.g. `/dev/sda1`). The data partition must already be formatted as ext4.

**A hashed password** for the admin user (from your workstation):

```bash
nix-shell -p mkpasswd --run "mkpasswd -m sha-512"
```

Enter the password you want to use when prompted. Copy the full output string beginning with `$6$`.

---

## Step 3: Generate an Age Key

The age key encrypts secrets before they are committed to the repository.

```bash
mkdir -p ~/.config/sops/age
age-keygen -o ~/.config/sops/age/keys.txt
```

The public key is printed to the terminal and begins with `age1`. Copy it. You will paste it into the generator in the next step.

---

## Step 4: Run the Generator

```bash
cd generator
nix-shell --run "python nixgen.py"
```

This opens a graphical window with five tabs. Fill in every field across all tabs before clicking Generate.

**Tab 1 — Host and Locale**

| Field | Description |
|---|---|
| Hostname | A short name for your server, e.g. `homeserver` |
| Domain suffix | Use `home` for local access via `.home` addresses |
| Timezone | e.g. `Europe/London` |
| Locale | e.g. `en_GB.UTF-8` |
| Keyboard layout | e.g. `uk` |
| Phone region | e.g. `GB` |

**Tab 2 — Network**

| Field | Description |
|---|---|
| Interface | The interface name from Step 2, e.g. `enp3s0` |
| IP address | The static IP you want the server to use, e.g. `192.168.0.55` |
| Prefix length | Subnet mask as a number. `24` is correct for most home networks |
| Gateway | Your router's IP address, typically `192.168.0.1` |
| Nameservers | Leave the default (`127.0.0.1`, `1.1.1.1`, `9.9.9.9`) |

**Tab 3 — SSH and User**

| Field | Description |
|---|---|
| SSH port | Change this from 22 to reduce automated scanning. The default in the generator is a non-standard port. |
| Admin username | e.g. `admin` |
| SSH public key | Paste the output of `cat ~/.ssh/id_ed25519.pub` from Step 2 |
| Password hash | Paste the `$6$...` string from Step 2 |
| Nextcloud admin password | Choose a strong password for your Nextcloud admin account |
| Age public key | Paste the `age1...` key from Step 3 |

**Tab 4 — Services**

| Field | Description |
|---|---|
| Nextcloud domain | e.g. `cloud.home` |
| Data directory | e.g. `/srv/data/nextcloud` |
| Max upload size | e.g. `16G` |
| AdGuard port | Leave the default |
| DNS settings | Leave the defaults |

**Tab 5 — Disks**

| Field | Description |
|---|---|
| OS disk | Full path to the OS disk, e.g. `/dev/nvme0n1` (not a partition, the whole disk) |
| Data partition | Full path to the data partition, e.g. `/dev/sda1` |

Click **Generate**. The generator writes `options/options.nix` and `options/secrets.yaml`. Return to the repository root:

```bash
cd ..
```

---

## Step 5: Encrypt Secrets

The `secrets.yaml` file currently contains plaintext credentials. Encrypt it before committing.

```bash
cd options
nix-shell -p sops --run "sops --encrypt --in-place secrets.yaml"
cd ..
```

The file now contains only encrypted values. It is safe to commit to a public repository.

## Step 6: Push to GitHub

```bash
git add .
git commit -m "Initial configuration"
git push
```

## Step 7: Deploy with nixos-anywhere

Run the following from your workstation. Replace the placeholders with your values.

```bash
nix run github:nix-community/nixos-anywhere -- \
  --flake github:YOUR_USERNAME/NixOSHome#HOSTNAME \
  root@TARGET_IP
```

- `YOUR_USERNAME` — your GitHub username
- `HOSTNAME` — the hostname you entered in the generator
- `TARGET_IP` — the current IP address of the target machine

nixos-anywhere connects to the target over SSH, partitions the OS disk using Disko, installs NixOS and applies the full configuration in a single operation. This takes several minutes.

The first boot will start all services but secrets decryption will fail. This is expected. The host's own age key has not been added to the SOPS policy yet. Complete Steps 8 and 9 before services that depend on secrets will start correctly.

---

## Step 8: Add the Host Key to SOPS

After the first boot, retrieve the host's SSH key and convert it to an age public key:

```bash
ssh-keyscan -p SSH_PORT TARGET_IP 2>/dev/null | \
  nix-shell -p ssh-to-age --run ssh-to-age
```

Replace `SSH_PORT` with the port you configured and `TARGET_IP` with the server's IP. The output is an `age1...` key. Copy it.

Open `options/.sops.yaml` in a text editor. Add the host key alongside the user key:

```yaml
keys:
  - &user_key age1abc...    # your key, already present
  - &host_key age1xyz...    # paste the host key here

creation_rules:
  - path_regex: secrets\.yaml$
    key_groups:
      - age:
          - *user_key
          - *host_key         # add this line
```

Re-encrypt `secrets.yaml` to include the host key:

```bash
cd options
nix-shell -p sops --run "sops updatekeys secrets.yaml"
cd ..
```

Commit and push:

```bash
git add options/.sops.yaml options/secrets.yaml
git commit -m "Add host key to SOPS"
git push
```

---

## Step 9: Final Rebuild

SSH into the server:

```bash
ssh -p SSH_PORT admin@TARGET_IP
```

Run the rebuild:

```bash
sudo nixos-rebuild switch --flake github:YOUR_USERNAME/NixOSHome#HOSTNAME
```

This pulls the updated configuration from GitHub, decrypts secrets using the host key and starts all services.

---

## Step 10: Verify Services

Once the rebuild completes, verify each service.

**SSH** — confirm you can log in on the configured port:

```bash
ssh -p SSH_PORT admin@TARGET_IP
```

**AdGuard Home** — point a test device's DNS to the server IP, then open:

```
https://dns.home
```

**Nextcloud** — open:

```
https://cloud.home
```

Log in with the admin username and the Nextcloud admin password you set in the generator.

To use the `.home` domains from other devices on your network, configure those devices to use the server's IP as their DNS server.

---

## Making Configuration Changes

Edit `options/options.nix` directly, then commit and push. On the server, run:

```bash
sudo nixos-rebuild switch --flake github:YOUR_USERNAME/NixOSHome#HOSTNAME
```

Automatic daily rebuilds run at 04:00 and apply upstream security patches atomically.

If a rebuild produces an unexpected result, reboot the server and select the previous system generation from the bootloader menu.

**Important:** Do not change settings through the AdGuard Home or Nextcloud web interfaces expecting them to persist. NixOS rebuilds the system from the configuration. Any runtime change made through a web interface is overwritten on the next rebuild.

## Troubleshooting

### SOPS decryption fails on rebuild

Check that the host key appears in `options/.sops.yaml` and that `sops updatekeys` was run after adding it. Verify the host's SSH key file exists:

```bash
ls /etc/ssh/ssh_host_ed25519_key
```

### Services not starting

Check service status on the server:

```bash
systemctl status nextcloud-setup
systemctl status adguardhome
systemctl status caddy
journalctl -u caddy -f
```

### SOPS command not found

The `sops` binary is not installed globally. All SOPS commands must be run inside a nix-shell that provides it:

```bash
nix-shell -p sops --run "sops ..."
```

### Internal .home domains not resolving on a client device

The `.home` domain names require the client device to use the server as its DNS server. Configure the DNS setting on the client device to point to the server's static IP address.

### Nextcloud shows a database error on first load

Wait thirty seconds and reload. The PostgreSQL service sometimes takes a moment to finish initialising on the first boot.

### Caddy HTTPS not working immediately

Caddy provisions certificates automatically on first request. Allow up to two minutes after the final rebuild before HTTPS works on all services.

## Notes on the Nextcloud Version

The flake pins Nextcloud to version 33.0.3 via an overlay in `flake.nix`. This prevents a known downgrade error that occurs when nixpkgs is pulled from the unstable channel and the bundled Nextcloud version changes between rebuilds. Do not remove the overlay without first verifying that the upstream Nextcloud and PostgreSQL versions in nixpkgs are compatible.
